Workflow Comparison and Reflection

Round 1: Vague Prompting
- Approach: Used a concise, high-level prompt without specifying constraints, edge cases, or exact structural requirements.
- AI Behavior: The model generated a generic implementation. While syntactically correct, it lacked the specific validation rules, UI design alignment, and detailed component states required for the capstone form.
- Outcome: Substantial manual refactoring and additional prompting were necessary to bridge the gap between the output and the project specifications.

Round 2: Precise Prompting & Workflows
- Approach: Applied structured prompting with clear constraints, exact component requirements, validation logic guidelines, and explicit verification steps.
- AI Behavior: The model acted as an expert developer, structuring the form with proper schema validation, handling edge states accurately, and ensuring code reusability.
- Outcome: The generated code was robust, cleanly structured, and fully integrated with the application state on the first iteration, significantly saving time and improving code quality.

Key Takeaways
- Specifying context, validation rules, and expected component structures dramatically improves the reliability and precision of AI-generated code.
- Using a structured workflow reduces iteration cycles and prevents architectural mismatch in frontend development.
